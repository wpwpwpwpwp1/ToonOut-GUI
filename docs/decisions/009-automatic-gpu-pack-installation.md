# 앱 버전과 분리한 GPU 팩 자동 설치

## 문제

GPU 가속 팩 설치 버튼은 앱 옆에 팩 파일이 없으면 파일 선택 창을 열었다. 일반 설치
프로그램은 CPU 앱만 포함하므로 다른 PC의 사용자는 별도 Release 자산을 직접 찾아
모든 분할 조각을 같은 폴더에 받아야 했고, 버튼 이름이 약속하는 설치 흐름과 달랐다.

## 검토한 선택지

- 파일 선택 방식을 유지하고 안내만 보강한다.
- 가장 최신 앱 Release의 GPU 팩을 받는다.
- 실행 중인 앱과 같은 버전의 Release에서 GPU 팩을 받는다.
- worker protocol별로 고정한 GPU 팩 Release에서 검증값이 고정된 팩을 받는다.

## 결정

NVIDIA GPU가 감지된 Windows x64 앱은 `GPU_PACK_RELEASE_TAG`로 고정한 Release에서
분할 GPU 팩을 자동 다운로드한다. GPU worker protocol이나 팩 내용이 바뀌지 않는 한
앱 패치 버전이 올라가도 같은 Release를 재사용한다. 앱에 포함된 manifest 크기와
SHA-256을 먼저 검증하고, 그 manifest가 선언한 각 조각의 크기와 SHA-256도 검증한 뒤
기존 원자적 설치 경계에 넘긴다. worker protocol이 다르면 네트워크 작업 전에 거부한다.

다운로드는 전체 진행률의 0~40%, 검증·압축 해제·설치는 40~100%로 표시한다. 모든
상태는 `[상태] n%` 형식이며 창을 닫아도 계속되고 다시 열 수 있다. 취소·실패·성공
모두 다운로드 임시 폴더를 정리하며 기존 설치는 새 팩 검증이 끝날 때까지 보존한다.

## 결과와 제약

- 팩을 다시 빌드하면 고정할 GPU 팩 호스트 Release에 모든 조각을 먼저 올리고,
  `scripts/build_gpu_pack.ps1`이 갱신한 고정 검증값과 `GPU_PACK_RELEASE_TAG`를 앱
  릴리스 전에 함께 커밋해야 한다.
- 앱 릴리스 워크플로는 고정된 GPU 팩 Release의 manifest와 모든 조각의 크기 및
  GitHub SHA-256을 검사한다. 하나라도 없거나 다르면 앱 빌드와 공개를 중단한다.
- 설치 시작 전에는 고정된 압축 다운로드 크기만 확인하고, 다운로드 뒤에는 팩이
  선언한 실제 압축 해제 크기를 다시 확인한다. 고정 10GB 상한을 요구하지 않는다.
- 다운로드·압축 해제·이전 버전 백업 디렉터리에는 소유 프로세스 ID를 넣는다.
  비정상 종료 뒤 다음 장치 확인에서 소유 프로세스가 사라진 임시 파일만 정리한다.
- 현재 자동 선택 대상은 Windows x64용 NVIDIA CUDA 12.8 팩 하나다. AMD·Intel GPU와
  Windows on ARM은 지원하지 않는다.
