# 003. 배치 자동 저장과 성능 정책

## 문제

긴 배치에서 마지막까지 기다린 뒤 결과 전체를 저장하면 중간에 앱을 중지했을 때 완료된 결과를 놓치기 쉽다. 동시에 일부 사용자는 ToonOut이 CPU/GPU 자원을 전부 사용하지 않기를 원한다.

## 검토한 선택지

- 모든 결과를 메모리 또는 임시 폴더에 둔 뒤 마지막에 한 번에 저장
- 작업 전에 출력 폴더를 필수로 선택하고 각 결과를 즉시 저장
- 출력 폴더 사전 선택은 선택 사항으로 두고, 선택했을 때만 즉시 저장
- 운영체제 전체 사용률을 감시해 정확한 CPU/GPU 퍼센트를 맞추기
- PyTorch 스레드·GPU 메모리 상한과 이미지 사이 휴식으로 앱의 부하를 제한하기

## 결정

출력 폴더는 처리 전에 반드시 정한다. 사용자가 `저장 위치 지정`을 먼저 누르지 않고 배경 제거를 시작하면 앱이 폴더 선택 창을 연다. 각 이미지는 완료될 때 충돌하지 않는 최종 이름으로 즉시 저장하며, 작업 완료 후 한꺼번에 저장하는 경로는 제공하지 않는다. 저장 위치는 앱 세션 안에서만 유지하고 다음 실행에는 자동 재사용하지 않는다.

기본 출력 이름은 원본 stem을 그대로 쓴 `파일명.png`다. 같은 경로가 이미 있으면 `파일명_no_bg.png`, 이후에는 `_2`, `_3` 숫자를 붙인다. 사용자는 저장 위치 옆 `이름 형식`에서 원본 stem 앞뒤의 접두사와 접미사를 정할 수 있다. 사용자 지정 형식의 충돌에는 `_2`, `_3` 숫자를 붙인다. 이름 형식은 사용자 설정으로 다음 실행에도 유지한다.

성능 모드는 `절약`, `균형`, `최대 성능`, `사용자 지정`을 제공한다. 정책은 PyTorch CPU 계산 스레드 수, 프로세스별 GPU 메모리 상한, 이미지 사이 휴식 시간으로 구성한다. 일시정지와 중지는 현재 이미지가 완료된 경계에서 적용한다.

## 이유

저장 흐름을 하나로 제한하면 사용자가 결과가 임시 상태인지 최종 저장 상태인지 구분할 필요가 없다. 긴 배치가 중지되거나 앱이 종료되어도 이미 완료된 결과는 출력 폴더에 남는다. 자원 정책은 앱 내부에서 예측 가능하게 적용할 수 있고 CPU/GPU 사용률을 계속 감시하는 복잡한 제어 루프가 필요하지 않다.

## 결과와 제약

- 원본과 기존 출력은 덮어쓰지 않는다. 기본 이름의 첫 충돌에는 `_no_bg`, 이후 충돌에는 숫자를 붙인다.
- 접두사와 접미사는 Windows 파일명 금지 문자, 제어 문자, 끝의 점·공백을 허용하지 않는다.
- 즉시 저장은 임시 PNG를 완성한 뒤 최종 경로로 교체한다.
- 출력 폴더를 취소하면 배경 제거를 시작하지 않는다.
- 앱을 다시 실행하면 저장 위치를 다시 지정해야 한다.
- GPU 메모리 비율은 할당 상한이지 GPU 연산 사용률 상한이 아니다.
- 매우 낮은 GPU 메모리 상한은 모델 로딩이나 추론을 실패시킬 수 있다.
- 일시정지는 진행 중인 단일 추론을 선점하지 않으므로 현재 이미지가 끝날 때까지 기다린다.
