# 링크 없는 모델 설치

## 문제

Hugging Face의 기본 캐시는 `snapshots` 파일을 `blobs`의 심볼릭 링크로 만든다.
Windows에서 앱의 실행 권한이나 프로세스 신뢰 수준이 링크를 만든 프로세스와 달라지면
이 링크를 따라가는 동작이 `WinError 448`(신뢰할 수 없는 탑재 지점)로 차단될 수 있다.
경로를 직접 로드하도록 바꿔도 스냅샷 파일 자체가 링크이면 같은 오류가 남는다.

## 검토한 선택지

- 오류가 난 사용자에게 Windows 개발자 모드나 관리자 실행을 요구한다.
- 기본 Hugging Face 캐시를 유지하고 `WinError 448`이 날 때만 파일을 복사한다.
- 고정 리비전 파일을 처음부터 앱 소유 폴더의 일반 파일로 내려받는다.

## 결정

`hf_hub_download`의 `local_dir` 방식을 사용해 각 고정 리비전 폴더에 일반 파일을
직접 저장한다. 런타임은 링크를 따라가지 않는 `stat`으로 필수 파일을 검사하며,
설치된 일반 파일은 네트워크를 다시 조회하지 않고 바로 사용한다.

링크 없는 형식에는 모델 루트에 작은 버전 표식을 둔다. `0.1.8` 이하의 구형 캐시는
첫 재설치 때 관리 대상 저장소만 정리하고, 새 형식의 안전한 부분 다운로드는 다음
설치에서 이어받는다. 관리 대상 여부를 검사하거나 삭제할 때 `Path.resolve()`로 링크를
따라가지 않는다.

## 결과와 제약

- 모델 설치에 Windows 개발자 모드나 심볼릭 링크 권한이 필요하지 않다.
- 앱을 관리자 권한으로 다시 실행해도 비관리자 프로세스가 만든 스냅샷 링크를
  통과하지 않는다.
- 기존 링크 캐시는 한 번 다시 내려받아야 하지만 이후 설치는 같은 오류 경로를 만들지
  않는다.
- 고정 리비전, 다운로드 메타데이터, 실제 모델 초기화가 함께 파일 손상과 호환성을
  확인한다.
