# ToonOut Desktop

ToonOut/BiRefNet을 이용해 여러 애니메이션 이미지의 배경을 로컬에서 제거하는 Windows 데스크톱 앱입니다.

현재 앱 버전은 `0.1.0`입니다.

실사용자 설치 전 확인할 운영체제, RAM/GPU 및 정확한 디스크 여유 공간은
[배포 요구 사양](docs/system-requirements.md)에 정리되어 있습니다.

## 개발 환경

- Windows 10/11 64-bit
- Python 3.12 64-bit

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

`einops`와 `kornia`는 BiRefNet 모델 코드가 직접 import하므로 개발 환경과 배포 파일에 포함합니다. 대상 사용자가 이 패키지를 따로 설치할 필요는 없습니다. 학습용 공식 요구사항에 포함된 OpenCV, SciPy, scikit-image, accelerate 등은 현재 추론 경로에서 사용하지 않으므로 앱 의존성에 추가하지 않습니다.

## 같은 앱에서 선택하는 NVIDIA GPU 가속

ToonOut은 CPU로 바로 실행되며, 오른쪽 위 처리 장치 버튼에서 같은 앱에 NVIDIA GPU 가속 팩을 추가할 수 있습니다.

- 호환되는 NVIDIA GPU가 있으면 `◆ GPU 가속 설치 가능`을 표시합니다.
- Release에서 `ToonOut-NVIDIA-GPU-Pack.partNN` 조각 전부와 `.parts.json`을 같은 폴더에 받은 뒤 `GPU 가속 팩 설치`에서 `.parts.json`을 선택합니다. 단일 ZIP을 직접 받은 경우에는 기존처럼 ZIP을 선택할 수도 있습니다. 팩 파일이 `ToonOut.exe` 옆에 있으면 앱이 자동으로 찾습니다. GPU 팩은 실행 코드를 포함하므로 ToonOut 공식 배포 팩만 설치해야 합니다.
- 설치 후 같은 버튼에서 CPU/GPU를 전환하거나 가속 팩만 삭제할 수 있습니다.
- 성능 모드와 일시정지는 worker 프로토콜 2가 필요합니다. 이전 GPU 팩이 설치된 경우 앱이 `GPU 팩 업데이트 필요`를 표시하며 CPU 처리는 그대로 사용할 수 있습니다.
- GPU 팩은 `%LOCALAPPDATA%\ToonOut\runtimes\nvidia-gpu`에 설치되며 관리자 권한이 필요하지 않습니다.
- 시스템 Python, PyTorch, CUDA Toolkit을 설치하지 않습니다. GPU worker에 PyTorch 2.7.1과 CUDA 12.8 실행 파일이 포함되며 최신 NVIDIA 드라이버만 필요합니다.
- 이미지와 모델은 GPU 사용 여부와 관계없이 로컬에서만 처리합니다.

현재 AMD·Intel GPU 가속은 지원하지 않습니다. 현재 빌드에서 GPU 팩 다운로드는 약 3.27GB, 설치 후 크기는 약 5.11GB입니다. GPU를 시작하지 못하면 CPU로 전환해 계속 사용할 수 있습니다. [PyTorch 공식 설치 조합](https://pytorch.org/get-started/previous-versions/)과 [NVIDIA 드라이버](https://www.nvidia.com/ko-kr/drivers/)를 기준으로 호환성을 확인합니다.

## 자동 업데이트

서명 키가 구성된 배포 빌드는 실행 후 GitHub Releases에서 새 버전을 자동으로 확인합니다. 새 버전이 있으면 설치 파일을 사용자별 업데이트 폴더에 자동 다운로드하고 Ed25519 서명, 파일 크기, SHA-256을 검증합니다. 검증이 끝나면 상단에 `업데이트 설치`가 나타나며, 한 번 누르면 ToonOut을 종료하고 사용자별 Inno Setup 설치를 실행합니다.

- 이미지 처리 중에는 설치 버튼이 잠기며 현재 작업을 중단하지 않습니다.
- 업데이트 확인이나 다운로드에 실패해도 현재 앱과 완료된 결과는 그대로 사용할 수 있습니다.
- 모델과 NVIDIA GPU 팩은 앱 본체 업데이트에 포함하지 않고 기존 사용자 데이터 위치에 유지합니다.
- 공개키가 비어 있는 개발 빌드는 외부 업데이트 요청을 보내지 않습니다.

첫 GitHub Release를 만들기 전에 저장소 소유자가 서명 키와 Actions Secret을 한 번 설정해야 합니다. 자세한 순서는 [릴리스 설정 문서](docs/releasing.md)를 따릅니다.

### GPU 가속 팩 빌드

GPU worker는 기본 앱과 다른 가상 환경에서 빌드합니다.

```powershell
py -3.12 -m venv .venv-gpu-worker
.\.venv-gpu-worker\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-gpu-worker.txt
.\scripts\build_gpu_pack.ps1
```

완성된 파일은 원본 ZIP과 `.sha256`, GitHub Release용 `.parts.json` 및 2GiB 미만의 `.partNN` 조각입니다. Release에는 `.parts.json`과 모든 `.partNN`만 올립니다. 대상 사용자는 직접 압축을 풀거나 조각을 합치지 않고 ToonOut 화면에서 `.parts.json`을 선택합니다.

## 첫 실행

앱 오른쪽 위에서 모델 상태를 확인할 수 있습니다.

- `● 모델 설치 필요`: 누르면 저장 위치를 고르고 모델을 설치합니다.
- `● 모델 설치됨`: 누르면 현재 위치를 열거나 모델을 이동·삭제할 수 있습니다.

모델이 없는 상태에서 처음 `배경 제거 시작`을 눌러도 같은 설치 창이 열립니다. 기본 위치는 `%LOCALAPPDATA%\ToonOut\models`이며, 다른 드라이브나 쓰기 가능한 폴더로 변경할 수 있습니다. 선택한 위치는 다음 실행에도 유지됩니다.

위치를 정하면 Hugging Face에서 BiRefNet 모델 구조와 ToonOut 가중치를 내려받습니다. 다운로드와 캐시를 위해 여러 GB의 여유 공간을 권장합니다. 이후 실행에서는 같은 위치의 파일을 재사용합니다.

앱은 BiRefNet 기본 가중치를 따로 내려받지 않습니다. 고정된 모델 구조를 `float32`로 만든 뒤 약 844MiB의 ToonOut 가중치를 직접 불러오므로, 동일한 기본 가중치를 다시 덮어쓰는 약 424MiB 다운로드를 피합니다.

기본 위치는 관리자 권한이 필요하지 않습니다. 사용자가 Windows 보호 폴더를 선택해 쓰기 권한이 필요한 경우에만 UAC 안내를 표시하고, 승인하면 앱을 관리자 권한으로 다시 실행합니다. 이때 선택해 둔 이미지 경로는 새 창에 복원됩니다.

모델 이동은 새 위치에 먼저 복사하고 설치 상태를 검증한 뒤 기존 모델 파일을 제거합니다. 모델 삭제는 ToonOut이 관리하는 BiRefNet 및 ToonOut 캐시만 대상으로 하며, 선택한 폴더의 다른 파일은 삭제하지 않습니다.

## 사용 흐름

1. PNG, JPG, JPEG, WEBP 이미지나 이미지 폴더를 선택하거나 앱 창 어디에나 끌어 놓습니다. 앱은 별도 시작 화면 없이 바로 대기열 작업 공간을 엽니다.
2. 왼쪽 대기열에서 배경을 제거할 이미지를 선택합니다. 새로 추가한 이미지는 자동 선택되며, 빈 공간을 드래그하면 사각형 영역을 한꺼번에 선택할 수 있습니다. Ctrl을 누른 채 클릭하거나 드래그하면 기존 선택에 이미지를 추가하거나 일부를 해제할 수 있습니다. `모두 선택하기`를 누르면 전체 대기열을 다시 선택합니다.
3. 대기열과 미리보기 사이의 경계를 오른쪽으로 끌면, 대기열 폭에 맞춰 작은 썸네일과 큰 썸네일로 자연스럽게 바뀝니다.
4. 아래 작업 표시줄의 `저장 위치 지정`에서 이번 실행에 사용할 출력 폴더를 고릅니다. 옆의 `이름 형식`에서는 원본 이름에 붙일 접두사와 접미사를 정할 수 있습니다.
5. 모델 설치 상태를 확인하고 `배경 제거 시작`을 누릅니다. 선택한 이미지만 처리되며, 저장 위치를 아직 지정하지 않았다면 폴더 선택 창이 먼저 열립니다.
6. 원본, 결과, 비교 보기를 이용해 결과를 확인합니다.
7. 결과는 이미지 한 장이 끝날 때마다 지정한 폴더에 즉시 저장됩니다.

창 안을 돌아다니는 츠나오는 앱 상태를 함께 보여 줍니다. 처음에는 잠들어 있고,
이미지를 추가하면 깨어나며, 배경 제거 중에는 그림을 그리고 작업이 끝나면 완성한
그림을 보여 줍니다. 마우스로 츠나오의 몸을 잡아 옮길 수 있고 빠르게 놓으면 창의
벽에 튕기며 날아갑니다. 비행 중에도 다시 잡을 수 있습니다. Windows에서
애니메이션 효과를 끈 경우 자세 애니메이션과 자동 걷기는 한 프레임으로 줄어듭니다.

원본 파일은 덮어쓰지 않습니다. 기본 형식은 `파일명.png`이며 대상 폴더에 같은 이름이 이미 있으면 `파일명_no_bg.png`, 그 이름도 있으면 `파일명_no_bg_2.png`처럼 숫자를 붙입니다. 사용자 지정 접두사나 접미사를 사용한 이름이 겹치면 `_2`, `_3`처럼 숫자를 붙입니다. 이름 형식은 앱을 다시 실행해도 유지됩니다.

저장 위치는 앱을 다시 실행할 때 자동으로 재사용하지 않습니다. 앱을 켤 때마다 `저장 위치 지정` 상태로 시작하며, 이번 실행 안에서는 같은 위치를 계속 사용하거나 버튼을 눌러 변경할 수 있습니다.

처리 중에는 `일시정지`와 `중지`를 사용할 수 있습니다. 두 동작 모두 현재 처리 중인 이미지의 결과를 망가뜨리지 않도록 그 이미지가 끝난 뒤 적용됩니다. 일시정지 후 `재개`를 누르면 남은 이미지부터 계속합니다. 이미 완료되어 자동 저장된 결과는 중지하거나 앱을 닫아도 출력 폴더에 남습니다.

처리 중에도 `이미지 추가`, `폴더 추가`, 창 전체 드래그 앤 드롭을 계속 사용할 수 있습니다. 새 이미지는 자동 선택된 대기 상태로 추가되고, 현재 배치가 끝나면 다음 배치로 처리됩니다. 처리 전에 선택을 해제하면 대기열에 남습니다. 사용자가 중지를 누른 경우에도 새로 추가한 이미지를 취소하지 않고 대기열에 남깁니다. 모델 추론은 메모리 사용량을 예측 가능하게 유지하기 위해 한 번에 한 장씩 실행합니다.

### 성능 모드

- `절약`: CPU 스레드 약 25%, GPU 메모리 상한 70%, 이미지 사이 1.5초 휴식
- `균형`: CPU 스레드 약 50%, GPU 메모리 상한 85%, 이미지 사이 0.5초 휴식
- `최대 성능`: 사용 가능한 CPU 스레드 전체, GPU 메모리 상한 100%, 별도 휴식 없음
- `사용자 지정`: CPU 스레드 수, GPU 메모리 상한, 이미지 사이 휴식 시간을 직접 지정

CPU 제한은 PyTorch 계산 스레드 수를 제한합니다. GPU 설정은 ToonOut 프로세스가 예약할 수 있는 GPU 메모리 상한이며 GPU 사용률을 정확한 퍼센트로 고정하지는 않습니다. 너무 낮은 GPU 메모리 상한은 모델 실행 실패를 일으킬 수 있으므로 그 경우 상한을 높이거나 CPU로 전환합니다. 설정은 다음 작업부터 적용되고 앱을 다시 실행해도 유지됩니다.
